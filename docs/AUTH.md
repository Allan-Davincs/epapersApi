# Phase 2 auth contract
Access tokens are returned in JSON and kept in SPA memory. Send Authorization: Bearer on private routes. Refresh tokens use HttpOnly, Secure, SameSite=Lax cookies scoped to /api/v1/auth. Development needs HTTPS for cookies. Both hosts must share a registrable domain; cross-site hosting needs a revised cookie policy.
Every POST/PATCH/DELETE requires Origin equal to APP_ORIGIN and X-EPapers-Client: web. Send credentials: include for refresh/login/logout. Preflight permits only the configured origin.
Registration, OTP resend, and forgot-password use generic responses. Register and forgot-password require Turnstile. Profile username changes reserve historical usernames permanently and apply the configurable 30-day cooldown. Roles cannot be supplied during registration.
Run the worker separately with environment loaded: node --env-file=.env --conditions=react-server --import tsx worker/index.ts. Email delivery uses an outbox and retries; it is at-least-once (a crash after sending can duplicate an email). SMTP daily budget defaults conservatively to 450 and can be configured. Confirm the sending limit of your Google account before production.
Admin login requires TOTP. Admin provisioning and secure enrollment of totp_secret are manual until Phase 6; never seed credentials. No admin management endpoints are exposed in this phase. Secret encryption and enrollment/recovery must be implemented before production admin provisioning.
Only cf-connecting-ip is trusted for IP limits. Restrict direct VPS access and have Cloudflare overwrite that header; otherwise clients can spoof it. Database counters keep limits consistent across processes.
Endpoints: POST /auth/register, /auth/verify-otp, /auth/resend-otp, /auth/login, /auth/admin/login, /auth/refresh, /auth/logout, /auth/forgot-password, /auth/reset-password; GET /auth/me, /auth/sessions, /auth/username-availability?username=; DELETE /auth/sessions/{id}; PATCH /users/me.
