# VPS deployment

Templates in `deploy/` are reviewable examples. No VPS, DNS, Cloudflare or bucket configuration was changed by this implementation. Use a supported Node.js release (CI uses 22), Nginx, and separate systemd API/worker services. Verify binary paths on the host. `tsx` is required by the worker and must remain installed; do not prune dev dependencies from this deployment layout.

1. Create an unprivileged `epapers` service user, `/srv/epapers/releases/<release>` and `/etc/epapers`. Keep the current release at `/srv/epapers/current`. Store production credentials in `/etc/epapers/api.env`, root-owned, mode 0600, outside the repository. Set exact HTTPS APP_ORIGIN/API_ORIGIN, cookie parent domain, TLS CockroachDB URL and independent JWT/refresh/IP/encryption keys. Do not use any `NEXT_PUBLIC_` credential variables.
2. In the release, run `npm ci`, `npm run db:generate`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run openapi`, and `npm run build`. Supply environment securely; avoid putting secrets in shell arguments/history. Use an operator migration credential for `prisma migrate deploy`; retain a database backup before migration. Seed the versioned department/program data once and verify flagged assignments against the prospectus. Seed creates no modules, users or passwords.
3. Standalone server output is `.next/standalone/server.js`. Copy `.next/static` into `.next/standalone/.next/static` and `public/` into `.next/standalone/public/` if present. Retain worker source, node_modules and package files alongside the standalone output. Switch `current` only after checks pass. Install both service templates and run `systemctl daemon-reload`; start API and worker independently. A failed worker prevents email, scanning, publishing and maintenance even when API health succeeds.
4. Replace placeholders in `deploy/nginx.conf`, install the TLS certificate/key, and validate with `nginx -t`. Cloudflare should proxy the API hostname using Full (strict) TLS. Permit port 443 only from current Cloudflare IP ranges, and operator SSH from approved addresses; keep 3001 bound to loopback. The API trusts CF-Connecting-IP only because direct origin traffic is blocked. Use authenticated origin pulls if available. Keep OS/Node/Nginx updates scheduled.
5. Configure cache rules to respect origin Cache-Control. Cache only successful public metadata GETs. Bypass `/auth/*`, `/admin/*`, `/users/me*`, `/uploads/*`, notifications, leaderboard, signed URLs and all mutation methods. Do not override no-store, vary the configured CORS origin, and avoid recording query strings or signed URLs in analytics. No credentialed response may be cached publicly. Add outer WAF/rate limits without weakening the database application limits.
6. Create separate private incoming/published R2 buckets with public/custom-domain access disabled. Scope API credentials to those buckets. Replace origins in the CORS templates with APP_ORIGIN, then apply them using the R2 dashboard. Allow incoming PUT with Content-Type and If-None-Match; published GET/HEAD with Range is needed for browser viewing. The browser sets Content-Type and If-None-Match and supplies the File body; it controls Content-Length automatically. It cannot manually set this forbidden header. Test the returned signed upload with an exact-sized File in each supported browser. Matching allowed headers/origins is required for presigned browser requests; see [Cloudflare CORS documentation](https://developers.cloudflare.com/r2/buckets/cors/) and [presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/).
7. Configure real SMTP app-password or Resend delivery, verify OTP/reset/approval/rejection messages. Check SPF/DKIM/DMARC and sending budgets. Bootstrap an initial admin only after an ordinary account is email-verified: securely set BOOTSTRAP_USERNAME and BOOTSTRAP_PASSWORD, then run `node --conditions=react-server --import tsx scripts/bootstrap-admin.ts`. It refuses when an admin already exists. Remove bootstrap variables afterward and test admin login/reauth using codes sent to the account email. Authenticator enrollment is no longer required. Apply migration 0008_admin_email_auth before enabling this flow.
8. Check HTTPS `/api/v1/health`, login/refresh/logout, denied guest admin access, ordinary curriculum search, verified upload/scan/publication/download, moderation XP once, soft-delete/restore, expired-object purge and maintenance flags. Use production-safe isolated accounts, not test fixtures. Verify CORS preflight and secure cookies from the actual SPA origin.

Use `journalctl -u epapers-api -u epapers-worker` for safe request IDs/status/duration and worker errors. Alert on API 5xx/latency, failed/old pending jobs, worker heartbeat, email budget exhaustion, ledger mismatch, database capacity/slow queries, backup age and object-purge failures. Disable raw URL/request-body logging at every proxy/exporter. The application logs do not include tokens, signed URLs, user names/emails or SQL error messages.

Graceful SIGTERM waits for worker processing; API systemd shutdown allows 30 seconds. Maintain one worker initially; jobs use optimistic leased claims and serializable retries. A rollback switches to a previously built release and restarts services, subject to migration compatibility. Do not undo migrations or restore over production automatically. Follow [backup/restore](BACKUP-RESTORE.md), restore into a separate target, and invalidate sessions before traffic resumes.

Host installation, service startup, `nginx -t`, certificates, firewall, DNS/WAF/cache rules, real R2 CORS/bytes and email checks remain operator tasks. Windows development checks do not establish that these Linux templates are installed or running.
